# Code standards
TypeScript strict mode, no untyped public boundaries or any. Kebab-case files, PascalCase types, camelCase functions, snake_case tables, documented stable API paths under /api/v1. Named protocol/domain constants; operational and business settings belong in validated configuration. No unrelated abstraction or dependency for trivial work.
Domain logic is pure; application orchestrates; adapters own I/O. Inject auth/config/logger/clock/providers. Public functions have concise purpose/parameters/return/error documentation. Comments explain rationale. TODOs require owner, issue and planned resolution.
API input/output/tool schemas validated, uniform error envelope {error:{code,message,details?}}, safe details only. Cursor pagination for unbounded collections with stable tie breaker. Document rate limits, idempotency and retry behavior. Conditional writes use expected revision.
Session handling follows current Supabase SSR/Next guidance, secure cookies and OAuth-compatible policies. Never roll custom crypto. Enforce owner MFA for privileged actions and central authorization. Sanitize generated rich text and reject unsafe URLs. SSRF checks must cover redirects/re-resolution if fetching directly. Uploads, if later enabled, require server type/size validation, isolated storage and malware checks before processing.
Use versioned migrations, reviewed RLS and composite constraints. No UI-only isolation. Transactions protect related writes. Don't log user messages, credentials or complete provider payloads; traces record selected tools, timings and redacted metadata. No private chain-of-thought persistence or display.
Maintain .env.example; introduce documented config files for non-secret structured defaults as needed. Server secrets never use public prefixes. Scope caches and usage reservations. Tenant settings are server-validated and cannot weaken platform security or global budgets.
Audit dependency maintenance/security before adding, lock exact resolved versions, CI dependency checks. Toolchain: formatter, ESLint, type-check, Vitest and Playwright or compatible alternatives verified at scaffold time. Domain >=90% coverage; targeted integration tests with controlled DB and fake providers; few critical end-to-end flows. Mock clocks and seed test data. Cross-tenant adversarial tests and meaningful provider contract tests mandatory.
CI: formatting/lint/type-check/unit tests, controlled integration/migration checks, critical e2e and dependency/security review before release. Document which checks ran; never mark unrun checks passed. Conventional feature-branch commits; no direct push to main.
